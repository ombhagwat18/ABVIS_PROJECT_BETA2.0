Production tab: what every control does

Written from the code in gui.py / machine_cycle.py. OPERATOR controls are visible in both modes; ENGINEER controls only in engineer mode. Nothing here has been run on the finished machine; the PLC link is real, the full inspect → reject cycle is not yet proven.

1. One bottle, step by step (all timing is by clock; there is no encoder)

t = 0 photo-eye X0 sees the bottle -> PLC ladder sets M2 (trigger) t = delay bottle reaches the camera (capture_delay_s) t = delay..delay+window N frames, spread evenly over the window (Frames / Window s) each frame: classifier + YOLO -> vote across frames -> ONE verdict t = decision PASS -> software writes M0 immediately REJECT-> software writes M1 at travel - T0 after the trigger t = travel PLC timer T0 ends, Y0 (reject cylinder) fires for T1; bottle is at the cylinder travel = reject_travel_s (stopwatch value) or Inspect->reject mm / Speed mm/s
Rule that decides everything: the REJECT command must go out before the bottle arrives by exactly the PLC's T0. So T0 must be shorter than the travel time, and the whole inspection (delay + window + AI time) must finish before travel − T0. Example: travel 4.5 s, T0 1.5 s → REJECT sent at 3.0 s → delay 0.6 + window 1.5 + AI 0.3 = 2.4 s ✓. Start is refused when T0 ≥ travel.

2. Buttons

ControlWhoWhat it does
START INSPECTIONOPRuns the start checklist, loads models, opens the line cameras, waits for a frame from each, then starts listening for triggers. Disabled unless every check passes.
STOPOPOrderly stop: no new triggers answered, bottles still being inspected end as FAULT, cameras close. Does not move the conveyor.
RESET FAULTOPClears a halt (3 FAULT bottles in a row, E-stop, crash) and acknowledges alarms. Refused while the E-stop input still reads pressed.
TEST INSPECTION (no PLC)ENGGrabs frames now, runs the models, shows the verdict and saves evidence. Never talks to the PLC. Use it to check the AI on a bottle held in front of the camera.
CAMERA TESTENGOpens the cameras only: resolution, fps, brightness, contrast, sharpness. Use it to focus and aim.
Capture test frameENGSaves the current frame to a test folder (for building the dataset from the real enclosure).
HALT (latch)ENGSoftware safety latch: while halted no PASS/REJECT is sent and every trigger becomes a FAULT bottle. Not an emergency stop – the hardware E-stop must cut power by itself.

3. Timing row (engineer)

FieldMeaningHow to set it
Inspect→reject mm, Speed mm/sDistance from the photo-eye to the reject cylinder and belt speed; travel = distance / speed.Measure with a tape and a stopwatch (marked bottle over a known length). Speed 5 mm/s is wrong for a 100 mm/s belt. Leave 0 to use T0 as travel. Overridden by reject_travel_s in settings.json.
T0 sPLC timer T0: delay from M1 to Y0. Must equal the ladder.Read the preset in ISPSoft (K15 = 1.5 s). Change both together.
T1 sPLC timer T1: how long Y0 stays on.Same rule as T0.
Late limit sA REJECT that would go out later than this past its deadline is not fired; the bottle is answered PASS, recorded FAULT, alarm to remove it by hand.0.2–0.3 s.
FramesHow many frames are analysed per camera per bottle (taken evenly across the window).6–10. More = steadier verdict, more AI time.
Window sHow long the bottle is watched once it reaches the camera.Time the bottle is visible (camera planner shows the maximum). 1.0–1.5 s.
Capture delay sWait after the trigger before the window opens: the time the bottle needs to travel from the photo-eye to the camera, minus half the window.python camera_planner.py computes it. 0 means "watch from the instant of the trigger", which is why bottles were "not found".
FAULT →What the machine does with a FAULT bottle: REJECT (safe) or PASS.Keep REJECT.
E-stop inputPLC input (e.g. X3) that reads the E-stop contact. Empty = not wired.Needs a rung in the ladder first.
SaveWrites these values to settings.json.
Speed calibration… / Line layout…Wizard that measures belt speed; editor for camera positions along the belt (stations).Use stations when the camera is not at the photo-eye.
Simulation check…Runs the whole software test list and the ladder simulation side by side.Run after any change. Ladder FAIL = ladder/settings wrong; self-test FAIL = code wrong.
Recipe…Which parts must be present (bottle, cap, label) and where.Per product.

Not in the screen yet: reject_travel_s, inspect_spread (settings.json only; close the app before editing it).

4. PLC buttons row (engineer; tick arm first)

ButtonWritesWorks only if
START conveyorM10the ladder has (X1 OR M10) → SET Y1. Your saved ladder does NOT
STOP conveyorM11the ladder has (X2 OR M11) → RST Y1. Not in your ladder
BOTTLE triggerM2always (the ladder reads M2). With the line running the bottle is inspected.
CLEAR STUCK TRIGGERM0an M2 stayed on with no answer (answers it PASS so inspection can continue).
Why START/STOP "do nothing": the software writes M10/M11 successfully (the log says OPERATOR_WRITTEN), but the ladder in final_year.isp has no rung that reads them (check R8 = ABSENT). Add these two rungs in ISPSoft, download to the PLC, and the buttons work. Until then use the physical X1/X2 buttons. The ladder is yours; this software never edits it.
Net A: | X1 M10 | (parallel) ----[ SET Y1 ] Net B: | X2 / M11 | stop: NOT X2 AND NOT M11 ----[ RST Y1 ] (keep your existing NC logic for X2) Also recommended: M10 / M11 reset themselves after one scan (pulse), e.g. a rung M10 -> RST M10 , M11 -> RST M11

5. What you see

ItemMeaning
Camera panesLive picture with component boxes (bottle / cap / label from YOLO) when the task includes detection. The line above the picture is the live verdict (about 3 per second), for display only.
LIVE: NO BOTTLE / GOOD / DEFECT x / FAULTDisplay. The PLC answer comes only from the frames taken after the trigger. With task "Classification" alone there is no presence check, so an empty belt can read DEFECT: use "Classification + Detection".
CURRENT BOTTLEThe last decided bottle: id, verdict, defect, per-camera result, command sent, times, and the evidence picture with boxes. It stays until the next bottle is decided.
CountersTOTAL, PASS, REJECT, FAULT, NOT INSPECTED (trigger lost or unanswered), MISSED REJECT (too late to fire), QUEUE (bottles waiting for their deadline).
TableOne row per bottle: confidence, scheduled reject time, command, status, PLC acknowledgement.
AlarmsCoded alarms with what to do. Every bottle is also written to the database (History / Database pages).

6. Task options

TaskStatus
ClassificationWorks (EfficientNet-B0, trained on a different background; accuracy on this enclosure is unproven). No presence check.
Classification + DetectionRecommended. YOLO says whether a bottle is there and finds cap/label; no bottle → FAULT, missing cap/label can be flagged.
DetectionComponents only, never a defect verdict on its own.
SegmentationNot usable: no model trained (polygons are not human-reviewed yet). Start is refused.

7. Operator vs engineer mode

Operator sees Production, History, Database and Health. Engineer sees everything, and the ENGINEER row on Production. Switch with the button in the top bar (optional PIN in settings.json engineer_pin). The Health page now has a live PLC I/O card: X0–X2, Y0–Y1, M0/M1/M2/M10/M11 states, read only.

8. Order to bring up the line

  1. Fix the ladder: T0 K15 (1.5 s), T1 as wanted; add the M10/M11 rungs. Put the same T0/T1 in the screen and Save.
  2. Measure belt speed, photo-eye → camera, photo-eye → cylinder. Run python camera_planner.py; enter Capture delay and Window.
  3. CAMERA TEST: focus, framing, the whole bottle visible.
  4. TEST INSPECTION with a good and a bad bottle held at the camera.
  5. START INSPECTION, then one bottle at a time, watching CURRENT BOTTLE and the PLC I/O card. Only then continuous feeding.
